# DustwireMP v0.3 — RDR1 build profile

The launcher records an executable fingerprint for the target RDR.exe:

- PE machine
- PE timestamp
- SizeOfImage
- file size
- SHA-256 of the complete executable file

By default, the launcher remains permissive for build discovery. It requires x64 but does not require an exact profile.

## Capture the first profile

1. Build with build.bat.
2. Run run_launcher.bat with the real RDR1 installation available.
3. Open logs/launcher.log.
4. Find the PE machine=... sha256=... line.
5. Copy those values into config/launcher.ini.

For a strict profile, every non-zero numeric field and the non-empty expected_sha256 value must match.

A minimal strict profile can use only the SHA-256:

~~~ini
expected_sha256=0123456789abcdef0123456789abcdef0123456789abcdef0123456789abcdef
~~~

Using the full fingerprint is preferred because it makes the profile explicit and easier to audit:

~~~ini
expected_machine=0x8664
expected_timestamp=0x12345678
expected_image_size=0x1000000
expected_file_size=123456789
expected_sha256=0123456789abcdef0123456789abcdef0123456789abcdef0123456789abcdef
~~~

Do not fill these fields with example values. They must come from the exact executable that the launcher is expected to support.

## Relationship to the game tick

The profile only identifies the executable build. It does not prove that a game-tick hook is correct.

The next implementation stage is:

exact RDR.exe hash -> verified code signature/address -> Rdr1GameTickSource

Until a code location has been verified against the selected executable, the client must continue using BootstrapTickSource.
